# 后端数据库资源说明

本目录保存 `labor_management_v2` 数据库脚本的后端部署副本。脚本可随后端源码一起打包、交付或部署，但不会因为文件位于 `resources` 目录就自动执行；是否自动迁移数据库必须由明确配置的数据库迁移机制决定。

数据库设计、实体关系、Excel 导入字段、事务规则和错误码的完整说明见：

[数据库结构与初始化说明](../../../../../../docs/sql/README.md)

## 文件说明

| 文件 | 用途 |
| --- | --- |
| `00_rebuild_schema.sql` | 删除并重新建立 `labor_management_v2`，创建表、索引和约束 |
| `01_seed_reference.sql` | 写入角色、业务默认值和导入模板定义 |
| `02_verify_schema.sql` | 只读检查数据库结构、约束和基础数据 |

执行顺序为：

```text
00_rebuild_schema.sql
→ 01_seed_reference.sql
→ 02_verify_schema.sql
```

`00_rebuild_schema.sql` 会删除目标数据库中的全部数据，只适合建立开发或测试基线。已有业务数据的环境必须使用经过评审的增量迁移脚本，不得直接执行重建脚本。

## 与 `docs/sql` 的关系

`docs/sql` 是数据库设计和人工维护的主目录，本目录是提供给后端打包与部署流程使用的副本。同名 SQL 文件应保持内容一致，不允许在两个目录分别演化出不同结构。

数据库结构发生变化时，应按以下顺序维护：

1. 在 `docs/sql` 修改并说明设计；
2. 同步三个 SQL 文件到本目录；
3. 检查同名文件内容或哈希是否一致；
4. 更新受影响的 Entity、Mapper、Service、DTO、VO 和接口；
5. 在空数据库完成脚本执行检查后再进入联调。

## 数据库与导入边界

- 数据库名称：`labor_management_v2`
- MySQL 版本：8.0 或兼容版本
- 学生和助教导入字段：公司、节次、学号、姓名、性别、行政班
- 学年学期由上传页面选择，通过接口参数 `termId` 传入
- 班级在学期和公司范围内由周次及连续课节唯一确定
- 节次示例 `1-1-2-17` 中，`1-1-2` 定位班级 `周1-1-2`，`17` 是学生班内编号
- 助教沿用学生主档，不重复保存姓名、性别和行政班

数据库脚本只提供结构和基础配置。应用层仍需实现文件解析、整批校验、事务回滚、角色权限、班级数据范围、错误响应和操作日志。

## 安全要求

- 本目录不得保存数据库用户名、密码或生产连接地址。
- 不得把临时测试数据直接追加到结构基线脚本。
- 不得在生产环境手工执行重建脚本。
- 不得只修改本目录而不更新 `docs/sql` 的主版本和说明。
