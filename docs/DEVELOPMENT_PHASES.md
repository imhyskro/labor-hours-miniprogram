## 阶段1：数据库与 Entity

待开始。

预计内容：

- 按业务规则建立数据库表（学生、班级、学期、劳动课程、节次、考勤、补课、助教、额外参加、成绩、重修、换证考试、操作日志、用户、角色等）
- 建立对应 Entity / Mapper / 基础 DTO
- 所有表使用 InnoDB + utf8mb4
- 主键统一 BIGINT AUTO_INCREMENT
- 核心外键建立索引
- 重要业务关系建立 UNIQUE 约束
- 禁止使用数据库级联删除
- 状态字段统一设计

## 阶段4：劳动课程、节次、延期

待开始。

预计内容：

- 劳动课程按学期管理
- 课程由多个固定节次组成
- 默认要求 11 次，数据库允许配置
- 课程延期：session_no 不变，planned_date 保留，actual_date 记录实际日期

---

## 阶段5：考勤、J/K、补课、封存

待开始。

预计内容：

- 考勤类型：NORMAL / LEAVE / ABSENCE
- 前端显示：数字 / J / K
- 请假补课完成后补课成绩作为最终成绩
- 旷课补课完成后最终成绩仍为 0
- 封存：实际发生日期 + 10 个自然日自动封存
- 封存后修改走修改申请审批流程

---

## 阶段6：助教、额外参加

待开始。

预计内容：

- 助教通过 sys_user.student_id 关联学生
- 助教只能操作被授权班级和节次范围
- 助教不能给自己评分
- 助教身份变化保留历史记录
- 额外参加必须保存具体明细，不能只保存 extra_count
- 额外参加次数按学期独立统计
- 额外参加不能抵扣正常劳动课程要求次数

---

## 阶段7：成绩、权重、总成绩、重修

待开始。

预计内容：

- 四项成绩：劳动实践 / 课程报告 / 理论学习 / 项目实践
- 默认权重：55% / 10% / 15% / 20%
- 权重总和必须为 100%
- 最终成绩四舍五入为整数
- 换证考试不参与四项成绩汇总
- 重修不能覆盖原始历史成绩
