# V2 数据库重构说明

本目录是一套从空库开始的数据库基线，不会修改旧库 `labor_management_test`。新库为 `labor_management_v2`。

## 执行顺序

1. `00_rebuild_schema.sql`：删除并重建 `labor_management_v2`，只对这个 V2 库具有破坏性。
2. `01_seed_reference.sql`：写入角色、默认业务配置、学生/助教导入模板定义。
3. `02_verify_schema.sql`：可选的只读结构检查。

旧目录中的 `init_schema.sql`、`phase*.sql`、`test_data*.sql` 属于旧模型，不能写入 V2 库，也不能与 V2 脚本混合执行。

## Excel 导入统一字段

学生导入和助教导入都使用以下六个必填表头，默认顺序为：

| 列号 | 表头 | 数据库去向 | 规则 |
| --- | --- | --- | --- |
| 1 | 公司 | `company`、`teaching_group` 及修读快照 | 必须匹配已有公司名称 |
| 2 | 节次 | `student_course_enrollment.section_code` | “班级编码-班内编号”，按最后一个连字符拆分 |
| 3 | 学号 | `student.student_no` | 学生唯一标识；助教导入也先落学生主档 |
| 4 | 姓名 | `student.student_name` | 去除首尾空格后不可为空 |
| 5 | 性别 | `student.gender` | 只允许“男”“女”“未知” |
| 6 | 行政班 | `administrative_class` | 保存业务方原始名称 |

“节次”不表示当天的自然课节，也不等于课次。例如 `A01-17` 表示班级编码 `A01`、班内编号 `17`；`1-3-4-17` 表示班级编码 `1-3-4`、班内编号 `17`。系统不再从节次中猜测周次或上课时间。

Excel 不增加“学年”“学期”列。上传前必须在页面选择学年学期，接口必须携带 `termId`；缺少时应在读取 Excel 前拒绝请求。

助教不是第二套重复人员数据。助教导入先按六列建立或更新学生、行政班和修读关系，再建立助教身份、账号和分组关系。因此姓名、性别、行政班只维护一份。

## 明确的错误提示

应用层写入业务表前必须验证整份文件。每条错误至少包含 `rowNo`、`columnNo`、`columnName`、`errorCode`、`message`、`rawValue`。数据库用 `data_import_batch` 与 `data_import_error` 保存批次和明细。

| 场景 | errorCode | 提示示例 |
| --- | --- | --- |
| 缺少整个表头 | `MISSING_COLUMN` | `缺少“行政班”列` |
| 表头重复 | `DUPLICATE_COLUMN` | `第6列表头“行政班”重复` |
| 单元格为空 | `EMPTY_CELL` | `第8行“学号”列为空` |
| 性别值错误 | `INVALID_GENDER` | `第8行“性别”值“其他”无效，仅允许男、女、未知` |
| 节次无法拆分 | `INVALID_SECTION` | `第8行“节次”格式错误，应为“班级编码-班内编号”` |
| 班内编号错误 | `INVALID_IN_CLASS_NO` | `第8行“节次”中的班内编号必须为正整数` |
| 公司不存在 | `COMPANY_NOT_FOUND` | `第8行“公司”值“果圆”不存在` |
| 教学分组不存在 | `GROUP_NOT_FOUND` | `第8行“节次”对应的班级编码“A01”不存在` |
| 文件内学号重复 | `DUPLICATE_STUDENT_NO` | `第8行“学号”与第3行重复` |
| 班内编号重复 | `DUPLICATE_IN_CLASS_NO` | `第8行“节次”与第5行使用了相同班内编号` |
| 已有普通修读 | `NORMAL_ENROLLMENT_EXISTS` | `第8行学生已有普通修读记录，如需再次修读请走重修流程` |
| 助教账号冲突 | `ASSISTANT_ACCOUNT_CONFLICT` | `第8行学号对应账号已存在且角色不允许转为助教` |

表头建议按名称映射；六个字段必须全部存在。如果还要求固定顺序，应先报告缺列，再报告“第 X 列应为某字段”，不能只返回“模板错误”。

## 导入事务规则

1. 建立导入批次，状态为 `UPLOADED`。
2. 一次性收集缺列、重复列错误。
3. 逐行检查六个单元格、公司、教学分组、重复数据及普通修读唯一性。
4. 只要有一条错误，保存全部错误，批次设为 `REJECTED`，业务表写入数必须为 0。
5. 全部通过后，在单个事务中写行政班、学生、修读关系；助教导入再写账号、角色、助教身份与分组关系。
6. 任意写入失败均回滚整批业务数据，批次标记为 `ROLLED_BACK` 或 `FAILED`。

## 关键模型变化

- 学生主档与学期修读拆开；学生通常只产生一次 `NORMAL` 修读，重修用新的 `RETAKE` 记录。
- 节次只表示“班级编码-班内编号”；课次单独保存，表示某天连续两节课。
- 一个教学分组只有一个当前教师，另用历史表记录教师变化。
- 助教与教学分组为多对多。
- 考勤、当前分数、不可变修改历史分表保存。
- 超期及二次修改通过申请和审批流水处理。
- 当前基础档案可以物理删除，关键事实表保存人员、公司、班级快照，外键用 `SET NULL` 或 `RESTRICT` 保留历史。
- 报表使用汇总过渡表，导出统一进入导出中心。

## 与现有后端的关系

现有 Java 后端仍使用旧表（如 `classes`、`attendance_session`，并把考勤与分数混在旧结构里），所以执行 V2 后现有后端不会自动兼容。正式切换前必须迁移实体、Mapper、Service 和接口；迁移完成前，让旧后端继续连接旧库。

建议迁移顺序：用户权限 → 学年学期/公司/教学分组 → 学生与助教导入 → 课次/考勤/分数 → 审批 → 通知/导出/日志 → 汇总任务。
