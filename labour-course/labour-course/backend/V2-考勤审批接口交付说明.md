# V2 考勤与修改审批接口（后端参考草案）

> 注意：本文只记录当前小程序后端提供的接口，不代表 Web 端已经采用这些路径，也不能替代 Web 端现有接口文档。Web 已有接口时，应先对齐字段和路径；确认复用当前后端后再把本文作为联调依据。

本文档供 Web 前端对接。所有接口统一使用 `Authorization: Bearer <token>`，响应外层为：

```json
{ "code": 200, "message": "操作成功", "data": {} }
```

## 角色与数据范围

- `ASSISTANT`：只能访问已分配的 `teaching_group`；可以打分、提交申请、查看和取消本人申请。
- `TEACHER`：只能查看和审批 `current_teacher_user_id` 为本人的教学分组。
- `ADMIN`：可以查看和审批全部教学分组。
- 小程序登录使用 `POST /api/auth/mini-login`，仅允许单一 `ASSISTANT` 身份。
- Web 登录使用 `POST /api/auth/login`。

## 基础查询和成绩保存

### 1. 教学分组

`GET /api/attendance/classes`

返回的 `id` 是 `teaching_group.id`。

### 2. 课次

`GET /api/attendance/sessions?classId={teachingGroupId}`

关键字段：

- `weekLabel`：格式为 `周x`。
- `scoreDeadlineAt`：数据库固化的截止时间。
- `editable`：当前是否处于普通打分窗口。
- `lockReason`：未到时间、已封存、已归档等原因。
- `unscoredCount`：排除助教身份学生后的未打分人数。

不再提供新建课次接口；课次由数据库迁移或排课流程写入 `course_session`。

### 3. 学生考勤与当前成绩

`GET /api/attendance/sessions/{sessionId}/records`

关键字段：

- `excludedFromScoring=true`：助教身份学生，不参与打分和未打分统计。
- `approvalStatus=pending`：待教师审批。
- `approvalStatus=approved`：已审批，处于限时修改窗口。
- `availableChangeRequestId`：保存修改时传回。
- `revisionCount`：已发生的修改次数。

### 4. 保存考勤与课次成绩

`PUT /api/attendance/sessions/{sessionId}/records/{studentId}`

正常分数：

```json
{
  "attendanceType": "NORMAL",
  "score": 5,
  "remark": "",
  "changeRequestId": 123,
  "changeReason": "按审批结果修正"
}
```

请假/旷课：

```json
{ "attendanceType": "J", "score": null, "changeRequestId": 123 }
```

`attendanceType` 只允许 `NORMAL/J/K`。第二次修改、`K -> J`、超期修改或已锁定记录必须携带有效的已通过申请；保存成功后申请变为 `USED`，不可重复使用，并向 `score_revision` 追加历史。

## 修改申请与审批

### 5. 提交申请

`POST /api/attendance/modification-requests`

```json
{
  "sessionId": 10,
  "studentId": 1001,
  "reason": "原考勤录入有误"
}
```

返回：

```json
{ "requestId": 123 }
```

同一申请人、同一成绩同时只能存在一条 `PENDING` 或未使用的 `APPROVED` 申请。

### 6. Web 审批列表

`GET /api/attendance/modification-requests?status=PENDING&sessionId=10`

查询参数均可省略。`status` 可为：

`PENDING / APPROVED / REJECTED / USED / CANCELLED / EXPIRED`

### 7. 申请详情

`GET /api/attendance/modification-requests/{requestId}`

返回申请、教学分组、课次、学生、当前成绩以及 `actions` 审批流水。

### 8. 审批决定

`PUT /api/attendance/modification-requests/{requestId}/decision`

通过：

```json
{
  "decision": "APPROVE",
  "comment": "同意修改",
  "editWindowHours": 24
}
```

驳回：

```json
{ "decision": "REJECT", "comment": "凭证不足" }
```

`editWindowHours` 可省略，省略时读取 `business_config.score.approved_edit_window_hours`。只有任课教师或管理员可以调用。

### 9. 取消申请

`PUT /api/attendance/modification-requests/{requestId}/cancel`

仅申请本人可取消 `PENDING` 申请。

### 10. 审批流水

`GET /api/attendance/modification-requests/{requestId}/actions`

动作包括：`SUBMIT / APPROVE / REJECT / USE / CANCEL / EXPIRE`。

## 数据表对应

- 课次：`course_session`
- 当前考勤：`attendance_record`
- 当前成绩：`score_record`
- 修改申请：`change_request`
- 成绩修改历史：`score_revision`
- 审批流水：`approval_action`
- 可调整参数：`business_config`

审批通过只产生一次限时修改授权，不直接改成绩。真正保存成功时才把申请置为 `USED`，确保审批和修改结果能够对应。
